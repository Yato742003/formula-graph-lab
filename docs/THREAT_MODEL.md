# FormulaGraph Lab Threat Model & Production Security Architecture

**Version**: 1.0 (Sprint 4.5 Hardening Baseline)  
**Standard Mapping**: OWASP Top 10 for LLM Applications (2025), NIST AI RMF 1.0, MITRE ATLAS  
**Scope**: FGL-H1 through FGL-H6 Security Boundaries and Execution Isolation  

Controls below are labeled current or planned. A design requirement is not evidence
that its enforcement exists; Section 4 is the release-gate status of this worktree.

---

## 1. System Overview & Security Principles

FormulaGraph Lab is a scientific reasoning and formula evolution platform combining Large Language Models (LLMs), Computer Algebra Systems (CAS like SymPy), and empirical execution microbenchmarks.

In this architecture, **the model and external scientific publications are treated as untrusted inputs**.

### Required security axioms
1. **Model Output is Untrusted Data**: Generated LaTeX, formulas, and proofs are hostile input until deterministically validated by static gates, typed verification vectors, and isolated kernels.
2. **Separation of Proposal from Verification**: Proposers cannot assert mathematical correctness, modify fitness scores, alter benchmarks, or approve candidates. Only authoritative verifiers issue CheckResult records.
3. **No Direct Code Synthesis / No Dynamic Execution**: Strictly zero eval(), exec(), or dynamic shell strings. Planned transformations must map to typed DSL operator manifests lowered to deterministic ASTs.
4. **Bounded Host-Process Execution**: Subprocess runners use isolated process groups, a secret-free environment, proxy null-routing, and memory/CPU bounds. This is not an air gap: containerized raw-socket and filesystem isolation is required before executing untrusted external code.
5. **Content-Addressed Provenance**: Current source evidence, analysis versions and check results are immutable/content-bound. Candidate IR and experiment artifacts must follow the same rule when Sprint 5 adds them.

## 2. Six Core Threat Vectors & Architectural Controls

### Vector 1: Untrusted Model Output Handling
* **Threat**: LLM generates malicious payloads, invalid AST structures, or attempts privilege escalation by injecting confirmation flags ("approved": true, "fitness": 1.0).
* **Controls**:
  - **Zero Dynamic Evaluation**: Strictly ban eval(), exec(), compile(), or shell invocations. Parsing is performed exclusively by grammar-based recursive descent AST engines (`app/formula_ast.py`) converting LaTeX/MathML into typed mathematical IR.
  - **Current Schema Invariants**: Contract reviews and check results use frozen, extra-forbidden Pydantic models. The Sprint 5 proposal schema must also reject server-owned identity, approval, fitness and benchmark fields.
  - **Preflight Static Gates**:
    - `MAX_CHECK_AST_NODES = 256` prevents parser complexity attacks.
    - All free symbols must match declared or inferred `SymbolContract` definitions; missing coverage yields `UNRESOLVED_SHAPE`.
    - Non-commutative symbols ($A \cdot B \neq B \cdot A$) preserve order unless commutativity is proven under active operator semantics (`core.multiply.v1`).
  - **Domain Obligation Analysis (FGL-H2)**:
    - Denominator and root singularity predicates are extracted over expression subtrees (e.g. $1/(a+b) \implies (a+b) \neq 0$).
    - Sprint 5 verification policy must prevent model-supplied assumptions from discharging obligations generated by the same proposal.

### Vector 2: External HTML & Retrieved Prose Sanitization
* **Threat**: Indirect Prompt Injection embedded in arXiv papers (malicious HTML tags, zero-width instructions, hidden CSS text, poisoned LaTeX math comments) attempting to hijack the reasoning agent.
* **Controls**:
  - **Ingestion Perimeter (`app/security.py`)**: Strict scheme enforcement (HTTPS only). Allowed hosts: `arxiv.org`, `export.arxiv.org`. Canonical format: Regex validated against `^(\d{4}\.\d{4,5})(v\d+)?$`. Ambiguous URL characters (`\`, `%`, `\r`, `\n`) trigger immediate rejection.
  - **Current SSRF Boundary**: Input and every redirect are canonicalized to HTTPS `arxiv.org/html/<modern-id>` with no credentials, custom ports, query or fragment. No general-purpose URL fetch is exposed.
  - **Current DOM Boundary**: The extractor parses HTML into normalized metadata, text and MathML records; raw source HTML is not rendered by the application or sent to a model today.
  - **Planned Prompt Containment (Sprint 5)**: Retrieved prose must be wrapped in source-tagged delimiters:
    `<untrusted_external_prose source_id="sha256-..." role="reference_only">`
  - Prompt instructions alone are not a control. The proposal adapter and DSL validator must enforce that external prose cannot create privileged fields or executable code.

### Vector 3: Queue & Tenant Isolation
* **Threat**: Cross-tenant data exfiltration, job spoofing, queue tampering, and resource starvation across multi-tenant research workspaces.
* **Controls**:
  - **Cryptographic Identity & Authorization (`app/worker_auth.py`)**: All actors possess distinct bearer tokens and bounded `WorkerPrincipal` records. Server-derived `workspace_id` is extracted strictly from verified credentials; clients cannot override tenant scope.
  - **Current API Boundary**: Worker credentials carry explicit workspace grants; symbolic check requests use an idempotency key bound to a server-computed request hash.
  - **Planned Queue Envelope (Sprint 5)**: Job messages will require immutable `tenant_id`, `workspace_id`, `job_id`, `request_hash`, and timestamp fields plus authenticated delivery.
  - **Planned Quotas (Sprint 5)**: Per-workspace concurrency and compute quotas are not implemented yet.

### Vector 4: Worker Subprocess Limits & Sandboxing
* **Threat**: Malicious or computationally unbounded symbolic expressions triggering SymPy hangs (denial of service), memory exhaustion, fork bombs, or host compromise.
* **Controls**:
  - **Host Process Limits (`app/verification.py`)**:
    - **Windows Platforms**: Bounded via Windows Job Objects (`JOBOBJECT_EXTENDED_LIMIT_INFORMATION`) with verified Win32 return codes:
      - `ProcessMemoryLimit = 256 MB`
      - `JobMemoryLimit = 256 MB`
      - Flags: `JOB_OBJECT_LIMIT_PROCESS_MEMORY | JOB_OBJECT_LIMIT_JOB_MEMORY | JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`
    - **POSIX Platforms**: Bounded via `resource.setrlimit(resource.RLIMIT_AS, (256MB, 256MB))` and `resource.RLIMIT_CPU`.
    - Memory exhaustion is caught immediately and returned as `error_code: "WORKER_RESOURCE_LIMIT"`.
  - **Real Wall-Clock Watchdogs & Tree Termination**: External watchdog monitors subprocess with strict timeouts (10 ms $\le$ timeout $\le$ 30,000 ms; default 2,000 ms). On timeout, the Windows Job Object or POSIX process group is terminated before pipes are drained.
  - **Output Validation**: The fixed symbolic worker emits one small JSON object. Output larger than `MAX_WORKER_OUTPUT_BYTES = 64 KB` is rejected after process exit; a streaming kill limit remains required before external worker code is permitted.
  - **Sanitized Environment Zero-Trust**: Workers inherit an explicit allowlist of system variables (`PATH`, `SYSTEMROOT`, `WINDIR`, `PYTHONPATH`, `TEMP`, `TMP`). Application credentials, service tokens, and database passwords are removed.
  - **Proxy Null-Routing (Defense in Depth)**: `HTTP_PROXY` and `HTTPS_PROXY` target `127.0.0.1:0`. This does not block raw sockets; container isolation is required before external worker code.

### Vector 5: Artifact Storage Integrity & Cryptographic Provenance
* **Threat**: Silent corruption, historical revisionism, cache poisoning, or tampering with verified benchmark results.
* **Controls**:
  - **Current Content Binding**: Source papers carry SHA-256 identities; analysis versions bind source and analysis hashes; check results bind request hashes. Candidate, dataset and execution-log artifact storage remains Sprint 5 work.
  - **Immutable Analysis Versioning (FGL-H5)**: Separation of immutable `EquationOccurrence` (raw extraction evidence) from versioned `FormulaAnalysisVersion`. Reparsing or algorithm updates append a new analysis version; raw extraction history is never mutated or overwritten.
  - **Migration & Rollback Receipts**: Idempotent migration scripts produce locked receipts binding exact equation UUIDs, source-only hashes, and stored-byte hashes. Rollback retires only versions introduced by that receipt, preserving pre-existing active versions.
  - **Append-Only Result Store**: Database nodes storing `CheckResult` enforce append-only policies. Duplicate executions return the stored receipt with `replayed: true`.

### Vector 6: Privilege Separation & RBAC (Proposer vs. Verifier)
* **Threat**: An LLM agent functioning as both candidate proposer and validator, leading to self-confirmation bias, hallucinated validity, or benchmark manipulation.
* **Controls**:
  - **Current Capability Definitions (`app/worker_auth.py`)**: `proposer`, `compiler`, `verifier`, `experiment`, and `evolution` have disjoint scope sets. Only the verifier check endpoint is wired today; the remaining endpoints must enforce these scopes when implemented.
  - **Human Review Boundary**: `ContractReview` records are written through the authenticated human-service route, not through worker role claims.
  - **Header Forgery Rejection**: Worker identities cannot self-promote by sending `X-FGL-Actor-Role` or `X-FGL-Workspace-ID`. Capabilities are determined exclusively by the authenticated bearer token.
  - **Research Execution Default**: Feature flag `FGL_ENABLE_RESEARCH_CHECKS` defaults to disabled (HTTP 503), preventing unauthorized check execution until explicitly enabled by server configuration.

## 3. OWASP Top 10 for LLM Applications (2025) Control Matrix

| OWASP Risk | Threat Vector | FormulaGraph Lab Mitigation |
|---|---|---|
| **LLM01: Prompt Injection** | Adversarial paper text attempting to force invalid proofs or alter fitness | No model proposal path exists today; Sprint 5 requires source delimiters plus strict proposal schema and DSL validation |
| **LLM02: Sensitive Information Disclosure** | Leaking worker tokens, database keys, or cross-tenant papers | Sanitized subprocess execution environments (`worker_env` allowlist), zero secrets in worker contexts |
| **LLM03: Supply Chain Vulnerabilities** | Compromised PyPI math libraries or tampered foundation model weights | Pinned hash dependencies (`uv.lock`, npm lockfiles), canonical arXiv ID regex validation |
| **LLM04: Data and Model Poisoning** | Research papers designed to inject subtle mathematical fallacies or vacuous truths | Multi-dimensional `VerificationVector` (discharged/conditional/unresolved/contradictory), domain obligation checks ($a+b \neq 0$) |
| **LLM05: Improper Output Handling** | Executing unparsed LaTeX or LLM-emitted Python code in host system | Strict AST parser (`app/formula_ast.py`), DOM sanitization, no dynamic code execution; container sandbox required before external worker code |
| **LLM06: Excessive Agency** | Autonomous loop spending unlimited compute or mutating parent graph nodes | Research endpoints disabled by default and scoped worker identities now; `ProblemSpec` budgets remain Sprint 5 work |
| **LLM07: System Prompt Leakage** | Extraction of internal prompts, scoring rubrics, or benchmarks | Secrets excluded from worker environments now; proposer/holdout isolation remains Sprint 5 work |
| **LLM08: Vector/Embedding Collisions** | Embedding collisions tricking search engine into equating incompatible formulas | Graphiti/embeddings used strictly for candidate retrieval; mathematical equivalence requires semantic hashing + formal CAS verification |
| **LLM09: Mathematical Hallucination** | LLM hallucinating universal validity for conditional identities | `CheckResult` multi-state vector (`supported`, `refuted`, `unknown`, `unsupported`, `timeout`, `error`); inconclusive proofs remain `unknown` |
| **LLM10: Unbounded Consumption** | Algorithmic complexity attacks (exponential simplification, fork bombs) | Preflight AST limits (`MAX_CHECK_AST_NODES = 256`), Windows Job Objects/POSIX rlimits, wall-clock timeout and process-tree termination; container quotas remain planned |

## 4. Current implementation status

This threat model documents the current baseline against the **Sprint 4.5 Release Gate** (`IMPLEMENTATION_PLAN.md:435-443`); it is not a compliance sign-off:
- [ ] Model proposal handling: deterministic formula parsing exists; the Sprint 5 proposal/DSL boundary is not implemented.
- [x] External HTML: Strict arXiv perimeter, DOM sanitized, prompt containment delimiters.
- [ ] Queue messages & tenant boundaries: workspace-scoped worker credentials exist; queue envelopes, authenticated delivery and quotas remain planned.
- [ ] Worker execution limits: host process limits and timeouts exist; raw-socket/filesystem isolation and streaming output termination remain planned.
- [x] Artifact storage: Content-addressed SHA-256, immutable analysis versions, locked migration receipts.
- [ ] Privilege separation: role scopes exist, but the proposer/compiler/evolution endpoints are not yet implemented end to end.
